# RAG 서비스 평가
> RAG 서비스는 단순한 LLM 서비스와 달리 "검색(Retrieval) + 생성(Generation)" 두 단계로 이루어져 있기 때문에, 어느 한 부분만 문제가 생겨도 전체 서비스 품질이 크게 떨어질 수 있습니다.
> 따라서 객관적인 평가(Evaluation)를 통해 문제를 발견하고 지속적으로 개선해야 합니다.

---
## RAG 서비스를 평가해야 하는 이유

---
### 1. 검색 품질이 답변 품질을 결정하기 때문
RAG는 LLM이 스스로 답을 만드는 것이 아니라, 검색된 문서를 기반으로 답변을 생성합니다.

```
질문
   ↓
문서 검색
   ↓
LLM 답변 생성
```
검색이 잘못되면 LLM도 잘못된 답변을 생성할 가능성이 높습니다.

---
예를 들어,

> 질문
> "회사 휴가 정책은?"

검색 결과

> ❌ 출장 규정

LLM 답변

> "출장은..."

LLM 자체의 문제가 아니라 검색기의 문제입니다.

---
### 2. LLM이 그럴듯한 오답(Hallucination)을 생성할 수 있기 때문
검색된 문서가 부족하거나 관련성이 낮으면 LLM은 부족한 정보를 추론하여 답변을 생성할 수 있습니다.

예를 들어,

질문

> "환불 기간은?"

검색 결과

> 배송 정책

LLM 답변

> "환불은 30일입니다."

실제 문서에는 30일이라는 내용이 없더라도 LLM이 자연스럽게 만들어낼 수 있습니다.

---
### 3. 검색은 잘 되었지만 답변 생성이 실패할 수도 있기 때문
예를 들어,

검색 결과

> 환불은 구매 후 14일 이내 가능합니다.

LLM 답변

> 환불은 30일입니다.

검색은 성공했지만, LLM이 문서를 제대로 활용하지 못한 것입니다.

---
### 4. 서비스 개선 효과를 객관적으로 확인하기 위해

예를 들어

기존

> Chunk Size : 1000

변경

> Chunk Size : 500

정말 좋아졌는지는 감으로 판단할 수 없습니다.

---
평가 결과를 비교해야 합니다.

| 변경 항목 | Faithfulness | Answer Relevancy |
| ----- | -----------: | ---------------: |
| 기존    |         0.82 |             0.78 |
| 변경 후  |         0.91 |             0.89 |

이처럼 수치 기반 평가를 통해 개선 여부를 확인할 수 있습니다.

---
### 5. 다양한 RAG 구성을 비교하기 위해

예를 들어
| 구성 | Retriever         |
| -- | ----------------- |
| A  | BM25              |
| B  | Vector Search     |
| C  | Hybrid Search     |

어떤 구성이 가장 좋은지는 평가 결과를 통해 결정해야 합니다.

---
# RAGAS 0.3.9 평가 컬럼

이 자료에서는 RAGAS 0.3.9 기준 컬럼명을 사용합니다.

| 컬럼명 | 의미 |
| --- | --- |
| `user_input` | 평가 질문 |
| `response` | RAG 체인이 생성한 답변 |
| `retrieved_contexts` | RAG 체인이 검색한 문맥 리스트 |
| `reference` | 기준 정답 |
| `reference_contexts` | 기준 정답을 만들 때 사용된 참조 문맥 |

예전 예제에서 자주 보이는 `question`, `answer`, `contexts`, `ground_truth` 컬럼명은 RAGAS 0.3.9에서 평가 입력으로 자동 인식되지 않을 수 있으므로 사용하지 않습니다.

---
## 평가 결과 해석

평가 점수는 단일 평균만 보고 끝내지 않습니다. 낮은 점수 샘플을 직접 열어 보고, 어떤 단계가 병목인지 분리해서 판단합니다.

| 관찰되는 패턴 | 의심할 문제 | 먼저 확인할 것 |
| --- | --- | --- |
| `context_recall`이 낮음 | 정답 근거가 검색 결과에 충분히 들어오지 않음 | chunk 크기, overlap, retriever `k`, embedding 모델 |
| `context_precision`이 낮음 | 관련 없는 문맥이 상위에 많이 섞임 | retriever `k`, MMR, metadata 필터, 문서 분할 방식 |

---
| 관찰되는 패턴 | 의심할 문제 | 먼저 확인할 것 |
| --- | --- | --- |
| `faithfulness`가 낮음 | 답변이 검색 문맥 밖의 내용을 말함 | 프롬프트의 근거 사용 지시, LLM temperature, 답변 길이 |
| `answer_relevancy`가 낮음 | 질문에 직접 답하지 않거나 불필요한 내용이 많음 | 프롬프트, 출력 형식, 질문 전처리 |
